# Native TexEnv parameter diagnosis

`TOUCHHLE_DS_TEXENV_TRACE=1` traces all six native GLES1 TexEnv f/x/i/fv/xv/iv variants, with API, target, pname, first raw32 bits and driver prior/error. Scalar/pointer arguments remain unchanged. It uses at most192 unique API/target/pname/error records per process. It does not recognize a scene, inspect a framebuffer, take screenshots, change parameters, suppress invalid calls or apply corrections. Default is off and cached once per process; that route calls the original driver exactly once, without reading pointer arguments or querying errors.

Diagnostic mode consumes GL errors to associate them with calls, then preserves the first existing pending synthetic error or the consumed prior/new error for the established GetError route. As with existing synthetic errors, one pending error is retained; the order of multiple OpenGL error flags is not guaranteed. Parameter tracing adds driver queries/locking and is not a release performance benchmark. Do not combine it with full COLOR_PROBE when attributing errors; that older path additionally handles color queries/capture and only directly traces TexEnvfv. No source/default light, ambient, box or chapter change is made here. An error without associated API parameters must not be attributed to a specific game call.

Deferred errors now belong to GLES1NativeContext and are borrowed by all four temporary-dispatch construction paths. The earlier per-dispatch Cell lost diagnostic/synthetic errors when a handle was dropped; the a97396e5 diagnostic APK is withheld and must not be installed or cited as preserving errors. Pure native-error lifetime/context-isolation tests cover the corrected storage contract.
