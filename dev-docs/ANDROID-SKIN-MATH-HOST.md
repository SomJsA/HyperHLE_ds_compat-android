# Calibrated Android host skin math (experimental, default off)

`TOUCHHLE_DS_SKIN_MATH=host` uses the same original-code fingerprints and checked owner-thread snapshots as shadow mode. It requires64 successful real native output/FPSCR comparisons separately for each function, then compares every256th call. A mismatch retains that call's original output and disables host replacement for the process. Unsupported inputs, disabled replacement and destination validation failure execute the unchanged original body. `TOUCHHLE_DS_SKIN_MATH_FORCE_FALLBACK_EVERY=17` deliberately exercises native fallback for diagnosis; it is not a player setting/default. Original IPA bytes and disk assets never change.

Host output is computed into independent owned storage before one complete revalidated destination copy. No guest memory/GL/Environment crosses threads. The void function returns through original LR with callee-saved registers/SP preserved. AAPCS32 allows volatile scratch/condition flags across this interface: https://github.com/ARM-software/abi-aa/blob/main/aapcs32/aapcs32.rst . Guest FPSCR controls/status are preserved and only sticky0x9F kernel flags are merged. The NEON kernel saves/restores host FPCR/FPSR, uses original standard SIMD rounding/FZ/DN and masks exception enables, with separate multiply/add.

Counters distinguish actual accelerated/native/forced/compared/unsupported/mismatch calls, capture/kernel/total handler elapsed. Counts include menus, entry, probes and result frames when those invoke skinning. Elapsed values include hooks, nested guest calls, bridge and scheduling, not exclusive CPU/GPU time. Shadow/profile overhead must not be called release FPS or a percentage gain.

`TOUCHHLE_DS_NATIVE_MATH_PROFILE=1` optionally fingerprints and times six unchanged native math routines: bone transforms, ES1/ES11 software normal/position ranges and TransformVector. Their first ARM PUSH is replayed with the original stack layout and host return trampoline; stack restoration is asserted. Two-register and five-register variants are tested. The Transform::Get routine does not have this prologue and is intentionally unhooked. Profile rows are inclusive: never add parent and child or call them CPU-exclusive time. Ordinary launches do not arm these hooks.

Repeat the production AndroidSkinMathBench against immutable original-code test segments, the actual wrapper/kernel and locked Dynarmic. It covers240 ordinary plus128 edge cases with all output bytes/FP flags, prologue replay, arbitrary guest FPSCR modes/merge via the production setter, and two-register synthetic PUSH register/stack/flags parity, followed by ABBAAB component timing. Pure policy and bounds tests run separately with rustc --test. Normal full release APK, current-data backup, actual installed hashes and real combat/input/pose/death tests are additional requirements. Default remains off until representative correctness and practical performance are established. Android3x/real60, resource/clock/streaming, UI/text/lights/boxes, saves/audio/weapons/hardware/final human gates all remain open.
