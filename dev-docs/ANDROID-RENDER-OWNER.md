# Experimental GL owner thread

Default off. TOUCHHLE_DS_RENDER_THREAD=sync forwards GLES1 calls with synchronous replies. =queue also enqueues pointer-free scalar state calls. DrawArrays/DrawElements, all pointer inputs/outputs, Flush/Finish and query results still wait. No async geometry is claimed before owned packet integration. A bounded256 command channel preserves order; one actor owns all GL contexts and physical swaps for a Window. Source NativeDriverState is initialized/borrowed only on that owner. No Environment/Window unsafe Send/Sync.

Opaque context tokens are explicitly detached before adoption. Additional context creation quiesces the owner and temporarily binds its selected context on the caller to preserve SDL share-with-current semantics, then detaches/adopts the new context. Actor deletion/shutdown deletes live contexts before Window destruction. Main SDL GLContext wrappers suppress their old destructor only for adopted contexts, preventing duplicate deletion. Unsupported context versions reject the diagnostic route; ordinary paths remain intact.

Generated ds_render_proxy.rs signatures come from GLES1Native. Pointer values cross only as numeric call tokens while the caller remains blocked through reply; client array data are consumed by synchronous draws. They must not be converted to async calls without owned snapshots and lifetime/barrier validation. Native-driver tests and real normal APK/GL/render/text/UI/input/lifecycle validation are required. This commit is not stable3x60, a complete queue backend or release default promotion.

Android background event drains/unbinds the window and parks the selected context on a worker-owned1x1 pbuffer of the same EGL config. SDL main-thread backup thus stores no active window context, allowing the window surface to be freed; the actor retains the live context. Background GL resource calls use parking, physical swaps are skipped. Foreground unbinds parking and the next command binds the new SDL window surface. EGL core calls are API21-compatible; config/pbuffer failure is explicit. Actual sleep/wakeup and lifecycle tests remain required.
