# SDL2 real-window ownership probe (default off)

`TOUCHHLE_DS_GL_HANDOFF_PROBE=1` runs once while creating the first native GLES1 context, before guest rendering. It loads bindings on the caller, explicitly detaches that context, transfers only opaque numeric handle tokens to a joined worker, then rebinds and validates SDL TLS on the caller. SDL objects live until after join. Main-thread work uses only a local hash; no Environment, guest pointer, GL context or Window object receives unsafe Send/Sync.

Worker exclusively owns current GL state, creates its own16x16 FBO/texture, checks eight clears using one fixture pixel each, deletes objects, restores bindings/clear color and calls SDL swap once. This is a boot-only self-drawn fixture, not game-frame capture or FPS measurement. Worker cleanup detaches on every normal/unwinding exit. Caller attempts rebind on spawn, worker and validation failure. This opt-in diagnostic is not a threaded game backend or a performance claim. Its actual normal APK/device result is required before using the protocol for an actor renderer. Window lifecycle, client-array snapshots, query barriers, owned resources, input latency/presentation and all R15 gates remain open.

Pinned SDL2 source: SDL_video.c stores current window/context in SDL TLS after backend MakeCurrent. Android SDL_androidgl.c forwards to EGL and locks Android_ActivityMutex around swap; no SDL3 thread-safety assumption is imported. https://wiki.libsdl.org/SDL2/SDL_GL_MakeCurrent documents compatible-window association, not a proof of the full concurrent SDL lifecycle.
